# 专属工作台 · Personal Workbench

一个**纯静态、零后端**的个人工作台网站：待办、投资跟踪（A股/ETF 实时行情）、记账本、小孩教育打卡、常用入口，并打通微信（快捷录入 + 云端多设备同步）。

> 数据默认保存在**你浏览器本地的 localStorage**，不依赖任何服务器与数据库，可直接托管到 GitHub Pages 免费运行。开启「微信同步」后数据存于云端，手机/电脑多设备实时同步。

## 功能一览
- 📋 **待办事项**：增删改、优先级、截止日、逾期提醒
- 📈 **投资跟踪**：自选股票/ETF 实时行情（东方财富接口）、成本与浮动盈亏、ETF 定投加仓建议
- 💰 **记账本**：收支流水、本月/累计结余
- 👧 **小孩教育**：识字闯关进度、学习/锻炼打卡、本周统计
- ✅ **习惯打卡**：自定义习惯、每日一键打卡、连续天数(🔥)统计、最近 7 天视图、打卡记录
- ⚡ **快捷入口**：常用工作/学习网站一键直达
- 💬 **微信同步**：微信快捷录入 + 云端多设备同步，见下文

## 本地预览
直接用浏览器打开 `index.html` 即可使用（无需安装任何依赖）。

## 部署到 GitHub Pages
**方式一（推荐，无需写代码）：**
1. 在 GitHub 新建仓库（如 `personal-workbench`），把本目录所有文件推送上去。
2. 仓库 `Settings → Pages → Build and deployment → Source` 选择 **Deploy from a branch**，分支选 `main`、目录选 `/ (root)`，保存。
3. 几分钟后访问 `https://<你的用户名>.github.io/personal-workbench/`。

**方式二（GitHub Actions 自动部署）：**
本仓库已内置 `.github/workflows/pages.yml`。推送 `main` 分支后自动部署，并在 `Settings → Pages` 选择 **GitHub Actions** 作为源。

## 个性化
点击右上角 **⚙ 设置**，可修改：
- **称呼 / 工作台名称**（如「汤工的专属工作台」）
- **微信同步（云端）**：填写 Supabase 地址 + 同步口令，开启多设备同步（可选）

## 打通微信（微信同步）
### 1) 微信快捷录入（纯前端，立即可用）
在「⚡ 快捷入口 → 💬 微信快捷录入」中，选择待办/记账/打卡/习惯，填写内容，点「生成分享链接 + 二维码」。
把链接或二维码发到微信（文件传输助手 / 自己），**用常用设备打开该链接**，即自动录入到本工作台。

> 配合「微信同步」（见下节）开启后：从微信打开链接录入的待办/记账/打卡会写入云端，自动出现在你所有已登录设备上。若未开启云端同步，数据只保存在「打开链接时所在的浏览器」，换设备请用「导出备份 / 导入备份」迁移。

### 2) 微信同步 = 云端多设备同步（Supabase）
默认数据存本地浏览器。若要在手机/电脑多设备实时同步，可接入免费的 [Supabase](https://supabase.com)。下面是一步步配置：

**第 1 步 · 注册并建项目**
- 打开 [supabase.com](https://supabase.com)，用 GitHub 账号登录（你已有 GitHub 账号，直接授权即可）。
- 点 **New project**，填项目名（如 `workbench`）、设一个数据库密码（记好；本应用不直接用该密码），区域选离你近的（如 Singapore / Tokyo），点 **Create project**，等约 1 分钟初始化完成。

**第 2 步 · 建数据表（一次性）**
- 左侧菜单进 **SQL Editor → New query**。
- 把本仓库 `supabase/schema.sql` 的**全部内容**粘贴进去，点 **Run**（或 Ctrl/Cmd+Enter）。
- 出现 `Success. No rows returned` 即成功。它会建 9 张表（todos / books / edu_records / edu_progress / watchlist / etf_advice / used_keys / habits / habit_logs）并关闭 RLS。

**第 3 步 · 取两个密钥**
- 左侧 **Project Settings → API**（齿轮图标 → API）。
- 复制两样：
  - **Project URL** —— 形如 `https://xxxxxxxx.supabase.co`
  - **anon public key** —— 一长串 `eyJ...`（可公开，安全）

**第 4 步 · 在工作台填三项并启用**
- 打开工作台，点右上角 **⚙ 设置**。
- 填三框：`Supabase URL` ← 第 3 步 Project URL；`Anon Key` ← anon public key；`同步口令` ← 自定义（相当于云端账号，建议够随机，如 `pB7GQSPQafvwtSCt`；**不同口令=不同数据集**）。
- 点 **测试连接**：提示「✅ 连接成功」说明表已建好、密钥正确；失败多半是第 2 步 SQL 没跑或 URL/Key 复制不全。
- 点 **保存设置**。右上角状态会从「💾 本地存储」变为「☁ 云端同步」。

**第 5 步 · 迁移已有的本地数据（重要）**
- 启用云端后页面改读云端（此时为空），原本地待办/记账会暂时看不见——**别慌，本地数据没丢**，只是没同步到云端。
- 迁移方法：在「⚙ 设置」清空三框保存（回到本地，数据回来）→「导出备份」下载 JSON → 重新填回云端三项并保存 →「导入备份」选该 JSON，数据即写入云端。之后日常都在云端，无需再导出。

**第 6 步 · 多设备 / 微信同步**
- 在另一台设备打开同一工作台，填**完全相同的 URL / Anon Key / 口令**，即可看到同一份数据。
- 微信里通过「⚡ 快捷入口 → 💬 微信快捷录入」生成的链接/二维码录入的内容，也会写入该口令对应的云端，立刻在所有设备出现。

> 这就是「微信同步」的完整含义：微信里录入 → 写入云端 → 所有设备可见，等价于一个轻量微信账号体系，且无需企业微信/公众号资质。

### 关于「微信扫码登录」
纯静态站点（GitHub Pages）无法独立完成微信 OAuth 扫码登录——它需要后端用公众号/企业微信的 Secret 换取用户信息，且回调地址须为已备案的 https 域名。因此本项目用上面的「同步口令 + 云端」方案替代扫码登录，达到同样的「多设备同一份数据」效果，且零资质门槛。若你以后确实需要原生扫码入口，可作为进阶项单独评估（需已认证公众号或服务号）。

## 数据安全与隐私
- 未开启同步时，所有数据仅存于你当前浏览器，**不上传任何服务器**。
- 开启同步后，数据存于你自己的 Supabase 项目（你完全掌控）；「同步口令」仅用于区分数据，请使用足够随机的口令。
- 定期使用「导出备份」下载 Json，换设备或清理浏览器前务必备份。
